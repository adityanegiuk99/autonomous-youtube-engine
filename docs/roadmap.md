# AYE Implementation Roadmap

The attached product blueprint defines the destination. This repository starts with no application implementation, so work proceeds in vertical slices and avoids representing planned integrations as operational.

| Phase | Deliverable | Status |
|---|---|---|
| 1. Foundation | FastAPI, Next.js shell, PostgreSQL development service, configuration, channel management | Partial: local bearer token, channel CRUD, and per-channel audience/editorial profile settings; multi-user identity remains |
| 2. Trend intelligence | RSS/provider adapters, normalization, deduplication, scoring, Trend Radar | In progress: RSS adapter and UI |
| 3. Research and strategy | sourced dossiers, claim extraction, opportunity scoring and routing | Partial: RSS source packs, manually authored source-linked claim dossiers and assessments, opportunity scoring, manual channel routing; automated claim extraction/verification pending provider |
| 4. Content generation | versioned scripts, formats, storyboard editor | Partial: versioned human script/storyboard API and Studio UI; scripts can attach immutable source dossier snapshots whose hashes flow into production approval; AI generation pending provider |
| 5. Video production | voice, licensed visuals, FFmpeg, captions, thumbnails, QA | Partial: rights-attested user media, PostgreSQL-backed FFmpeg worker queue, blueprint-target 1080p output, scene captions plus WebVTT sidecars, thumbnail, technical QA; no TTS/stock integration or word-level caption sync |
| 6. Publishing | OAuth, channel verification, human approval, resumable private-first upload | Partial: exact-version human approval and local private-only schedule records; OAuth/upload not started |
| 7. Analytics and learning | snapshots, comparisons, evidence-backed recommendations | Partial: normalized CSV import, sample-aware descriptions, and human-managed control/treatment experiment tracking; live API pending OAuth |
| 8. Integration audit | operational security, recovery, costs, integration verification | In progress: persistent Approval Center, cautious analytics learning hypotheses, workflow event history, PostgreSQL-backed production queue, replay guard, durable render attempt records with stale-attempt recovery, worker liveness heartbeats, configurable per-storyboard attempt ceiling, measured local render resource dashboard, read-only media integrity audit, and operator recovery runbook; full audit pending |

Video Studio can attach up to 20 same-trend manual dossier versions to a script. Each script version snapshots the selected evidence and includes it in its content hash, which is then included in production approval fingerprints. This carries citation provenance downstream without independently verifying claim accuracy.

## Phase 1 exit criteria

- Local services can be configured without committing secrets.
- API and dashboard have a clear, working foundation.
- Channel configuration CRUD persists records and does not imply OAuth connection.
- Database schema changes have a migration path.
- README explains setup and current limitations.

Phase 1 has a working local bearer-token gate and channel CRUD UI, but lacks multi-user identity. Phase 2 has RSS ingestion, deduplication, a source-diversity/freshness score, and Trend Radar; Google Trends and YouTube discovery need provider/API quota setup. Phase 3 adds RSS source packs, versioned manually authored claim dossiers with HTTPS citations and explicit human assessment notes, the blueprint's weighted opportunity score with explicit human inputs, and manual channel assignment. Dossiers are traceability aids: URLs are not fetched, and claims are not independently fact-checked; automated extraction and verification remain pending provider setup. Phase 4 stores versioned human-authored scripts and storyboards with content hashes and a Studio editor; AI generation awaits provider configuration. Phase 5 supports user-supplied image/audio uploads with rights attestation, a PostgreSQL-backed background FFmpeg worker, scene-level text overlays, thumbnail output, scene-timed WebVTT captions, and technical container QA. It does not generate narration, source stock media, synchronize word-level captions, or fact-check editorial content. Phase 6 records human approval against exact content hashes and supports local private-only schedules with separate human-reviewed metadata fingerprints. YouTube OAuth, channel verification, resumable uploads, and external scheduling need Google credentials and are not implemented; no external publish action is available. Phase 7 imports normalized cumulative analytics CSVs, reports latest-per-video descriptive metrics with sample-size labels, and tracks human-managed control/treatment experiments; live Analytics API collection still needs OAuth and real channel data. Phase 8 adds a persistent Approval Center for saved production renders and prior human decisions, authenticated media playback, and exact-hash review. A local snapshot/restore runbook is documented. Analytics emits sample-count-labeled exploratory hypotheses from imported video metrics only when at least 10 videos are present; these are explicitly non-causal and do not auto-change strategy. Per-idea workflow events record creation, version saves, render successes/failures, human decisions, and local schedule changes transactionally; failed render attempts clean partial files and are retryable. Production render attempts are durably queued and claimed by the Compose worker using PostgreSQL row locks. Operations shows worker heartbeats and flags stale queued and running attempts for explicit recovery after `AYE_PRODUCTION_STALE_AFTER_SECONDS`; recovery cleans deterministic partial outputs where possible, but does not resume from FFmpeg checkpoints or schedule automatic retries. Production render requests for identical idea/storyboard inputs serialize through a PostgreSQL advisory lock; intact passing renders may be reused, while active duplicate work is rejected. Attempt totals are capped by `AYE_MAX_PRODUCTION_ATTEMPTS`. Automated retries, resumable FFmpeg checkpoints, off-host backups, retention, restore drills, full service monitoring, provider/cloud cost controls, and the full integration/security audit remain pending. Local render wall time and media bytes are measured, but no financial cost estimate is available. The media integrity audit compares local referenced files with stored checksums and reports up to 100 orphan filenames without modifying storage.
